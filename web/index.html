// what this is

Most "reasoning" work right now scales one of three knobs: bigger model, longer chain-of-thought, more samples-and-vote. ZEON is a bet on a fourth axis: structure the latent computation itself.

Concretely: take a pretrained transformer, freeze its embedding and last few decoder layers and LM head, and graft a small virtual machine on top. That VM has a workspace of slots, a library of operators, a verifier that scores intermediate states, and a halting policy trained with RL. It thinks for K adaptive steps in latent space, then emits a token.

Today (v0.1, this PR) we are at phase 1 of 7 — the workspace bank exists, every flag works, 26 unit tests are green. Benchmark validation is the very next thing.

// why this should work (and where it might not)

the bet

A single hidden vector recurrently updated for K steps is just an RNN with adaptive depth. That's Universal Transformer (Dehghani '18) + PonderNet (Banino '21) and it's well-explored territory. It is also not enough — the "scratchpad" is one vector, and there is no way to keep separate hypotheses, intermediate evidence, and a running conclusion at the same time.

Humans don't think with one number. We keep multiple things in mind at once, and they update at different rates. So ZEON adds a structured workspace: 16 learned slots per token, sticky per-slot gating, multi-head intra-token attention for reads, a diversity loss to prevent collapse. The slots' roles are not labelled by humans; they specialise via gradient.

the risk

The honest list of ways this can fail:

  • slot collapse — every slot learns the same vector, we burned compute on nothing. Mitigation: diversity loss + per-slot role embeddings.
  • dead branch — workspace contributes a residual that's gated to zero, no gradient flows. Mitigation: we explicitly avoid zero-init on the output projection and verified gradient flow in unit tests.
  • cost — workspace state is (B, T, S, D), one workspace per token. With S=16 this is 16× the activation memory of the equivalent recurrent core. For our 16k-context bet that's manageable, but if S grows we revisit.
  • operator routing collapse (phase 2) — router always picks the same operator. Mitigation: load-balance loss, Gumbel-softmax warm-up, top-k routing.
  • verifier outsmarts body (phase 3) — process reward model becomes the whole brain. Mitigation: cap verifier size at body/4 and label-smooth.
  • RL variance explodes (phase 4) — halting policy gradient ping-pongs. Mitigation: warm-start from supervised halt, REINFORCE → PPO transition, KL prior baseline.

For each of these the ROADMAP has an explicit "if it falls over" exit. If a phase doesn't work, we either build phase N' or skip ahead. We do not spend a year defending our self-image.

// how it works

Forward pass, in compact form: 

h_0 = OuterStack(Embed(x))           # transplanted, frozen
W_0 = InitWorkspace(h_0)             # per-token slots, role-embedded

for t in 1..K:
    op   = Router(W_{t-1}, h_0)              # phase 2: pick operator
    read = ReadHeads(W_{t-1}, h)             # multi-head intra-token attn
    W_t  = WriteHeads(op(W_{t-1}, read))     # gated sticky update
    score_t = Verifier(W_t, x)               # phase 3: process reward
    if HaltCritic(W_t) > halt_threshold:    # phase 4: RL-trained halt
        break

h_K = Project(W_K)
y   = LMHead(h_K)                    # transplanted, frozen

The outer stack is taken from a base model (Qwen2.5-1.5B in our smoke tests) and frozen — we do not retrain knowledge. The LVM loop is what we train. By Phase 5 it ships with K parallel rollouts and an Energy Head picking the most-trustworthy one.

the 5 invariants we will not bend

  1. HF compat — must load via AutoModelForCausalLM.from_pretrained. If this breaks, the phase fails.
  2. ablation flag per component — flag off must measurably hurt the score. If it doesn't, the component is decorative and we delete it.
  3. benchmark per phase — no opinions-only "phase done" declarations.
  4. inference ≤ 5× base — past that, just use a bigger model.
  5. 16k context — we are not chasing 2M context. The bet is "short context + deep latent thinking".

// faq

Q. Isn't this just a Universal Transformer / PonderNet rebrand?

Phase 0 is, on purpose. Phase 0 sits inside the UT ∩ PonderNet ∩ Recurrent-Depth-Transformer intersection deliberately — it's the baseline we have to beat. The actual bet starts at Phase 1 (structured workspace), and the bet sharpens at Phase 2 (learned operator library, sparse top-k routing). If after Phase 2 we still can't show specialisation patterns and ablation-driven score drops, the thesis is in trouble and we'll say so.

Q. What stops slots from collapsing into the same vector?

Three things, increasing in strength: (1) per-slot learned role embeddings break symmetry at init so gradient has something to specialise from; (2) a diversity loss penalising mean off-diagonal slot cosine similarity; (3) if both fail, Phase 1's fallback is to introduce Slot Attention-style competition for input mass. The diversity-loss synthetic test lives in tests/test_workspace.py.

Q. How is the workspace contribution made bit-for-bit identical to Phase 0 at init?

It isn't, and that's deliberate. The textbook trick is to zero-initialise the output projection so the residual is exactly zero. But that also zeros the gradient on every upstream workspace projection (LoRA-style dead-branch trap), so no workspace parameter ever learns. We chose instead to make the workspace output a small perturbation at init (≈ 5–15% relative norm in the unit-test config) and provide the ablation guarantee at the flag level: use_workspace=False → the module is literally not in the graph. There's a 30-line essay about this in zeon/workspace.py.

Q. Inference cost?

Hard ceiling: 5× the base model. Past that, ZEON is no longer an interesting bet — a bigger base model is just cheaper. Our Phase 6 (self-distillation in latent space) exists specifically to compress mean step-count back down once the slow Phase 4 + Phase 5 versions have trained.

Q. What base model are you transplanting from?

Smoke tests are on Qwen2.5-1.5B because it fits one consumer GPU; transplant code is generic over Llama-style architectures. The choice of base is deliberately a variable — Phase 7 success criteria specify "at parameter-matched comparison", not "at base-specific comparison".

Q. What if this doesn't work?

Then we publish the failure, in detail, with numbers. We have explicit "if it falls over" exits at every phase. The least interesting outcome of ZEON is a 12-month ablation study of what doesn't work for adding structured latent reasoning to a frozen transformer — and even that is more useful than another "we scaled it harder" post.

Q. Can I use this in production?

No. v0.1 doesn't even have validated benchmark numbers yet. We are not at "ship it" — we are at "argue with the design".

Q. Why the typos and slightly-off grammar?

Because we wrote this ourselves, late at night, and we didn't pass it through a copy-editor. The roadmap is the roadmap; the grammar is just garnish.
